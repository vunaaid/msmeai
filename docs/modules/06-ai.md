# Group 6: AI Layer — Hệ Thống AI Agents

> **2 packages + 1 app** — Đây là lớp AI xuyên suốt toàn bộ platform.  
> Multi-LLM Provider: Claude + Gemini + Ollama (self-hosted).  
> Dual mode: Full AI (tự động) hoặc Assistant (hỗ trợ con người).  
> Có thể deploy hoàn toàn độc lập với mọi module nghiệp vụ.

## Package: `packages/llm` — Multi-LLM Provider

### Mô Tả
Abstraction layer cho nhiều LLM provider. Business logic không biết đang dùng Claude hay Gemini hay Ollama — chỉ gọi LLM client chuẩn. Hỗ trợ failover tự động khi provider lỗi.

### Chức Năng

**Provider Adapters:**

| Provider | Model gợi ý | Dùng khi |
|----------|-------------|----------|
| Claude (Anthropic) | claude-sonnet-4-6 (mặc định), claude-opus-4-7 | Reasoning phức tạp, tạo nội dung dài, phân tích tài chính |
| Gemini (Google) | gemini-2.0-flash (nhanh/rẻ), gemini-2.5-pro | Tasks đơn giản, volume cao, multimodal |
| Ollama (self-hosted) | llama3, qwen2.5-coder, mistral | Dữ liệu nhạy cảm không muốn gửi cloud, offline mode |
| LM Studio (self-hosted) | Bất kỳ GGUF model | Dev local, test |

**Provider Selection Logic:**
```typescript
// Ưu tiên theo thứ tự:
// 1. Per-agent config trong skill.md (frontmatter: preferred_provider)
// 2. Task type rules (complex → Claude, fast → Gemini)
// 3. Data sensitivity rules (sensitive → self-hosted)
// 4. Fallback chain nếu provider lỗi / rate limit

interface ProviderConfig {
  provider: 'claude' | 'gemini' | 'ollama' | 'lmstudio';
  model: string;
  endpoint?: string;      // chỉ cần cho self-hosted
  apiKey?: string;
  maxTokens?: number;
  temperature?: number;
  priority: number;       // 1 = ưu tiên cao nhất, fallback theo thứ tự tăng dần
}

interface TaskRoutingRule {
  task_type: string;      // 'financial_analysis' | 'content_draft' | 'data_extraction'
  condition?: string;     // 'value > 100M' | 'contains_pii'
  preferred_provider: string;
}
```

**Prompt Caching (Claude):**
- System prompts và skill files được cache (5 phút TTL)
- Giảm latency và cost đáng kể cho repeated calls cùng agent
- Cache prefix: company_id + skill_file_hash

**Unified Interface:**
```typescript
interface LLMClient {
  chat(messages: Message[], options?: ChatOptions): Promise<ChatResponse>;
  stream(messages: Message[], options?: ChatOptions): AsyncIterable<string>;
  embed(text: string): Promise<number[]>;  // Cho semantic search
}

// Tất cả providers implement interface này
// Business code chỉ dùng LLMClient, không import provider cụ thể
```

**Usage Tracking:**
- Log mỗi LLM call: provider, model, tokens, latency, cost estimate
- Per-company cost dashboard
- Rate limit monitoring, alert khi gần limit

### Entities

```

  id, company_id, provider, model, endpoint, api_key_encrypted,

}
LLMUsageLog {
  id, company_id, provider, model, agent_id,
```

## App: `apps/ai-worker` — AI Task Worker

### Mô Tả
Standalone Node.js app xử lý AI tasks bất đồng bộ qua BullMQ. Nhận tasks từ web app, xử lý với đúng agent, trả kết quả về. Không block UI, có retry, có timeout, có dead letter queue.

### Queues & Handlers

```
Queue: ai-tasks (concurrency: 5)
  Handlers:
  ├── orchestrator.handler   → Phân loại & dispatch đến agent
  ├── c_suite.handler        → CEO, CFO, CMO, CTO, CHRO, GĐ KD, GĐ PR, KTT
  ├── manager.handler        → Trưởng phòng 6 departments
  ├── staff.handler          → Nhân viên 6 departments
  └── briefing.handler       → Tạo AI morning briefing (cron mỗi sáng 7:30)

Queue: ai-approvals (concurrency: 3)
  Handlers:
  └── approval.handler       → Xử lý approval requests từ AI

Queue: ai-escalations (concurrency: 2)
  Handlers:
  └── escalation.handler     → Timeout → leo thang
```

### Task Flow

```typescript
// Web app push task vào queue
await aiQueue.add('process', {
  company_id: 'xxx',
  trigger: {
    type: 'user_message' | 'scheduled' | 'event',
    source_role: 'giam-doc-kinh-doanh',
    user_id: 'yyy',
    content: 'Tôi muốn review tất cả deals sắp đến hạn tuần này'
  }
});

// Worker xử lý:
// 1. Load skill file cho role
// 2. Build system prompt (skill + context hiện tại từ Visibility)
// 3. Gọi LLM với tools available
// 4. LLM ra quyết định → gọi tools hoặc tạo approval request
// 5. Ghi audit log
// 6. Trả kết quả về web app qua SSE/WebSocket
```

## Module 22: AI Agent System (UI + Backend)

### Mô Tả
Phần UI và backend API của hệ thống AI. Gồm AI Console (nơi user chat với AI agent của role mình), Approval Inbox (duyệt yêu cầu từ AI), và AI Admin (cấu hình agents, providers, mode).

### Chức Năng

**AI Console (Chat Interface):**
- User chat với AI agent đúng role của mình
- AI agent nhận diện context: ai đang chat, role gì, phòng ban gì
- AI trả lời trong context của role (CFO chat → CFO agent trả lời)
- Hiển thị reasoning: "Tại sao tôi làm vậy"
- Lịch sử chat theo session + search
- Đính kèm file (AI đọc được nội dung)
- Voice input (speech-to-text cho mobile)

**Approval Inbox:**
- Danh sách approvals chờ người dùng duyệt (từ AI + từ workflows)
- Mỗi approval: full context + AI recommendation + pros/cons
- Approve / Reject / Request thêm thông tin (1 click)
- Delegation: ủy quyền cho người khác khi vắng

**Task Queue Dashboard:**
- Xem tất cả AI tasks đang chạy / đã chạy trong scope của mình
- Trạng thái: queued → running → completed | failed
- Xem chi tiết: input, reasoning, output, tools called
- Retry task bị lỗi

**AI Admin Panel (cho SUPER_ADMIN):**
- **AI Mode toggle**: Full AI ↔ Assistant mode (per company)
- **Agent config**: enable/disable agent, set preferred LLM provider per agent
- **Authority thresholds**: điều chỉnh ngưỡng tự động hóa (VD: tự approve chi tiêu < 10M)
- **LLM provider config**: API keys, endpoints, model selection, priority order
- **Usage & Cost**: dashboard chi phí LLM theo provider, agent, tháng
- **Skill file viewer**: xem nội dung skill.md đang active cho từng role

**Dual AI Mode:**

```
FULL MODE (ai_mode = 'full'):
  Khi AI quyết định và trong thẩm quyền:
  → Thực thi ngay (gọi tools, cập nhật data)
  → Ghi audit log
  → Notify người liên quan

  Khi vượt thẩm quyền:
  → Tạo approval request
  → Notify approver
  → Chờ quyết định

ASSISTANT MODE (ai_mode = 'assistant'):
  AI CHỈ:
  → Phân tích, tóm tắt, đề xuất
  → Tạo draft (email, báo cáo, proposal)
  → Trả lời câu hỏi
  → KHÔNG gọi bất kỳ tool nào thay đổi data
  → Mọi action cần user confirm trước
```

**26 Agents Theo Org Chart:**

```
Orchestrator (1):
  - Phân loại request → dispatch đến agent phù hợp
  - Multi-agent coordination
  - Context sharing giữa agents

HĐQT (2):
  - Chủ tịch HĐQT: tổng hợp báo cáo, chuẩn bị tài liệu họp HĐQT
  - Thành viên HĐQT: review tài liệu, ghi nhận ý kiến

C-Suite (8):
  - CEO: tổng hợp company KPIs, theo dõi OKRs, schedule C-Suite meetings
  - CFO: cash flow monitoring, tự động reconcile, dự báo tài chính
  - KTT (Kế toán trưởng): kiểm soát bút toán, chuẩn bị BCTC
  - CMO: campaign performance, content calendar, lead metrics
  - GĐ Kinh doanh: pipeline management, quota tracking, deal escalation
  - GĐ PR: media monitoring, reputation alerts, content scheduling
  - CTO: sprint tracking, incident routing, tech KPIs
  - CHRO: HR metrics, hiring pipeline, workforce planning

Managers (6):
  - Trưởng phòng TC-KT, MKT, KD, PR, KT, NS:
    Phân công task, theo dõi workload team, báo cáo tuần lên C-Suite

Staff (6):
  - NV TC-KT, MKT, KD, PR, KT, NS:
    Hỗ trợ công việc cụ thể: nhập liệu, draft content, CRM update, CV screening...

Special (4):
  - Hợp đồng TC-KT: xử lý workflow hợp đồng tài chính
  - Phòng TC-KT: consolidated finance agent
  - Phòng KD: sales ops automation
  - Support Agent: customer ticket routing (nếu Support module bật)
```
